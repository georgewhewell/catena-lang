# BF16 support

`stdlib/default/bf16.hex` adds BF16 kernel values to the standalone
default stdlib. The runtime ABI stays unchanged: pass buffers through
`MemRef`/`MemOwn`, uploading BF16 words with `Runtime::mem_u16`. BF16 and packed
BF16 pairs are internal values rather than
new exported scalar argument types. Existing F32 modules do not include the
BF16 SDK header or helpers.

## Compiler and code generation additions

| Interface | Purpose and generated representation |
| --- | --- |
| `bf16` / `bf16x2` | Two-byte SDK BF16 values and four-byte aligned packed pairs, including typed global/shared views. |
| `stdlib.numeric.numeric/signed/floating.bf16` | Erased evidence selecting BF16 for existing generic arithmetic, comparisons, zero, min/max, negation, exp, sqrt and rsqrt. Operands/results remain BF16; transcendental operations require device execution. |
| `f32.to-bf16` / `bf16.to-f32` | Explicit boundary conversions for reductions, inverse factors, constants and returned logits. |
| `bf16x2.pack/low/high` | Assemble and extract the two BF16 lanes without float conversion. |
| `bf16x2.dot-f32` | Two native BF16 products accumulated into F32 using `__builtin_amdgcn_fdot2_f32_bf16`. This cannot be replaced by widened F32 multiplications. |
| `memoryelement.bf16/bf16x2`, `mem_cast_own/ref_bf16/bf16x2`, `global_own/ref_bf16/bf16x2`, `global_bf16/bf16x2_to_mem` | Add the BF16 element choices to the existing typed memory API, preserving capabilities, allocation/readability/ownership evidence, bounds, alignment and byte-count validation. |

Memory operations use the `stdlib.gpu.memory.` prefix. Existing typed reads,
writes, allocation, shared layouts, barriers and folds work with these element
types. Packed loads/stores use byte copies so reading BF16 scalar storage as
pairs does not introduce C++ aliasing violations. Indexing counts pairs for
`bf16x2`, and counts scalar elements for `bf16`.

Native packed dots require device execution on HIP gfx11: gfx1100–1103 and
gfx1150–1153. CUDA packed dots and host dots are rejected by code generation;
unsupported HIP architectures fail device compilation with an explicit error.
There is no widened device fallback. Scalar code can target HIP or CUDA using
the matching SDK; CUDA compilation was not available in the implementation
environment.

SDK BF16 arithmetic is typed BF16 and rounds to BF16 at its operation boundaries.
The SDK/compiler may implement some scalar operations with F32 machine
instructions on hardware lacking a matching scalar instruction. This API does
not promise a BF16 machine instruction for every scalar operation. Packed dot
products do require the native BF16 instruction. F32 is intentional for their
accumulator and other model reductions.

## Helpers expressed in Hex

Model-specific norm multiplication, RoPE, SwiGLU, causal softmax, projection
tiling, reduction trees, workspace reuse and the decoder loop remain Hex
composition. They are not new compiler primitives. Use shared numeric operations with BF16 evidence
for ordinary arithmetic, F32 for reductions, typed global/shared views for
storage, and the existing phase/barrier interfaces for shared-memory sequencing.
No raw byte-length, unchecked raw BF16 read/write, MemRefs registry, or narrowing
integer primitive is introduced.

## Verification

```sh
cargo test --offline --locked -p catena-lang --lib \
  --test bf16 --test stdlib_sources --test stdlib_compile
```

The BF16 fixture checks typed memory, native dot emission, scalar SDK operations,
shared numeric interfaces, rejected host operations and CUDA dot rejection. The adjacent SmolLM2
repo contains an opt-in emitted-kernel CPU executor and gfx1151 ISA compilation
test. Its CPU emulation macro is test-only and never used by the runtime.

## Shared operations and compatibility

Numeric operations select their C++ lowering from the operand type. F32 retains
its existing lowering; BF16 arithmetic uses SDK calls such as `__hmul_rn` to
preserve each operation's rounding and prevent contraction. Comparisons/min/max
share expression rendering. BF16 exp/sqrt/rsqrt use `hexp`/`hsqrt`/`hrsqrt`; their
SDK implementations can use F32 internally when matching instructions are absent.

Construct BF16 constants using existing constants and `f32.to-bf16`; select
values using `core.if`. U16 remains a runtime checkpoint storage format and a
private C++ packing detail, with no new Hex U16 type or bitcast primitives.

This replaces the initial BF16 arithmetic, comparison, one, selection, FMA and
U16 bitcast primitives. Programs using them must migrate to the shared numeric
operations or Hex composition. BF16 model adapters instantiate these interfaces;
F32 programs, native-dot requirements and the runtime ABI remain unchanged.

Optional real-SDK host numerical checks require ROCm clang but no GPU:

```sh
CATENA_BF16_HOST_TESTS=1 cargo test --offline --locked -p catena-lang --test bf16
```

They check rounding ties, signed zero, subnormals, infinities, NaNs and comparisons
against an independent BF16 rounding reference. Device transcendental behavior is
also checked by emitted-kernel tests in the adjacent model repository.
